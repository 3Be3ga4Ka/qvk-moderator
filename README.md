# 💜 QVK Moderator v2.0

Telegram-бот модератор форума QVK: детерминированные правила + бесплатный **Cloudflare Workers AI**, база D1, управление командами и кнопками Telegram. **За явные тематические нарушения удаляет сообщение с предупреждением (режим можно выключить), не блокирует. По отдельной настройке удаляет исключительно служебные уведомления Telegram о вступлении/выходе.**

## Правила
- 🐛 **Баги:** версия QVK `testXX`, что не работает, шаги воспроизведения, ожидаемое/фактическое поведение, фото или видео по возможности. Предложения направляются в идеи.
- 💡 **Предложения:** идеи новой функции/улучшения, цель и ожидаемое поведение. Жалобы на ошибки направляются в баги.
- 🏅 **Значки:** заявки с VK ID или ссылкой на профиль. Не принимать пароли или токены; фактическая выдача значка **не автоматизирована**.
- 💬 **Общение:** свободная беседа, без тематических предупреждений.
- 📦 **Бета-релизы:** объявления и APK публикуют только администраторы из `ADMIN_IDS`; остальным мягкое предупреждение, сообщение не удаляется.

Явная путаница веток удаляется с предупреждением по детерминированным правилам без зависимости от ИИ. Сомнительные сообщения перепроверяются Workers AI; решения только от ИИ никогда автоматически не удаляются. Уверенность AI для предупреждения должна быть от 0.87. Когда AI недоступен, действуют только уверенные правила. Медиа без подписи не штрафуются. Это не комплексная антиспам/антимошенническая система, изображения и видео нейросеть не анализирует. Повторных автоматических санкций нет.

## Развёртывание в Cloudflare
1. В Cloudflare Dashboard создай **D1 database** с именем `qvk-moderator-db`.
2. Скопируй её `database_id` в `wrangler.toml` вместо `REPLACE_WITH_D1_DATABASE_ID`. Workers AI подключен декларацией `[ai] binding = "AI"`.
3. Через Node.js/Termux или Cloudflare Builds выполни `npm install`, затем `npx wrangler d1 execute qvk-moderator-db --remote --file=./schema.sql` и `npx wrangler deploy`. Для автоматических деплоев выбери **Workers & Pages → Create → Connect to Git** и репозиторий `3Be3ga4Ka/qvk-moderator`. Build command: `npm run deploy`, предварительно настроив D1 и секреты.
4. В Cloudflare Worker Settings → Variables and Secrets добавь секреты **BOT_TOKEN**, **WEBHOOK_SECRET**, **ADMIN_IDS** и по желанию **CHAT_ID**. BOT_TOKEN выдаёт @BotFather, WEBHOOK_SECRET — случайная строка 8–256 допустимых ASCII символов, ADMIN_IDS — числовые ID разрешённых модераторов через запятую. CHAT_ID — Telegram chat ID группы (например, `-100...`), ограничивает действия ботом в одной группе.
5. Зарегистрируй Telegram webhook (только в приватной оболочке, не в Github и не в переписке):
   ```bash
   curl -X POST "https://api.telegram.org/bot${BOT_TOKEN}/setWebhook" \
      --data-urlencode "url=https://<worker>.<subdomain>.workers.dev/webhook" \
      --data-urlencode "secret_token=${WEBHOOK_SECRET}" \
      --data-urlencode 'allowed_updates=["message","callback_query"]'
   ```
6. В BotFather отключи Privacy Mode (`/setprivacy` → Disable), добавь бота в группу и отправь в каждой соответствующей ветке `/bind bugs`, `/bind ideas`, `/bind badges`, `/bind chat`, `/bind releases`. Затем `/panel`, `/topics` и `/stats`.

### Команды администратора
`/panel`, `/topics`, `/stats`, `/rules`, `/enable`, `/disable`, `/ai_on`, `/ai_off`, `/joins_on`, `/joins_off`, `/bind <type>`. Панель настроек **следует открывать внутри группы QVK**, поскольку настройка привязана к chat_id. В личке она будет относиться к личному чату, а не к группе.

### Важные ограничения
- Пользовательские сообщения не удаляются, предупреждения остаются видимыми. Служебные уведомления о вступлении (`new_chat_members`) и выходе (`left_chat_member`) автоматически удаляются (по умолчанию включено). Для отключения `/joins_off`, для включения `/joins_on` либо соответствующие кнопки `/panel`. Боту необходимо право администратора **Delete messages** (`can_delete_messages`). Удаление служебных сообщений не использует Workers AI. Администраторам из `ADMIN_IDS` модерация не применяется.
- Из исходного текста в D1 пишется только краткая причина предупреждения; также сохраняются Telegram ID пользователей, статистика и настройки.
- Текст сомнительных сообщений передаётся Cloudflare Workers AI. Сообщи об этом участникам.
- Квота Workers AI Free: 10 000 neurons в сутки; модель `@cf/meta/llama-3.1-8b-instruct-fp8`. Фактическая доступность модели/тарифа проверяется при развёртывании.
- В данной версии обработка webhook асинхронная с `waitUntil`; при падении обработки после HTTP 200 событие может быть потеряно. Для строгой надёжности нужны Queues/retries.
- Повторные update_id защищены D1; старые записи `processed`/события пока не удаляются автоматически.
- Для телеграм-форума `message_thread_id` и формат команд должны соответствовать актуальному Telegram Bot API.

## Проверка удаления уведомлений
Пригласи тестовый аккаунт в группу, дождись служебного сообщения о вступлении: оно должно исчезнуть. Если остаётся, проверь право **Delete messages**, `CHAT_ID` и журналы Cloudflare. Проверить кнопку можно в `/panel` внутри группы. Настройка применяется только к сообщениям, появившимся после включения.\n\n## Проверка
`npm test` — тесты детерминированных правил. До боевого развёртывания протестируй на отдельной группе, затем проверь `/health`, `getWebhookInfo` и отправку предупреждений.

## 🛡 Антиспам v1.3

Работает во всех ветках форума, включая «Общение»:
- Повтор одного и того же сообщения **3 раза за 120 секунд**.
- Флуд **7 и более сообщений за 20 секунд** от одного пользователя.
- Сокращённые/трекерские ссылки из ограниченного набора доменов (bit.ly, tinyurl.com, t.co, cutt.ly, grabify.link, iplogger.org, iplogger.com), а также **4+ HTTP(S)-ссылки** в одном сообщении.
- Действия записываются в `events`, видны через `/stats`.
- Исключены боты и доверенные администраторы из `ADMIN_IDS`.
- По умолчанию только **предупреждение**. Удаление сообщений о явном спаме — только после явного включения администратора.
- ИИ не используется на этапе антиспама; классификация тем остаётся прежней.

### Новые кнопки /panel и команды
`/spam_on`, `/spam_off` — включить/выключить антиспам.
`/links_on`, `/links_off` — включить/выключить проверку ссылок.
`/spam_warn` — оставить сообщения, выдавать предупреждения (по умолчанию).
`/spam_delete` — включить удаление срабатываний антиспама, требует права **Delete messages** у бота.

**Важно:** это эвристики, возможны ложные срабатывания. Участники могут намеренно использовать сокращатели или отправлять много полезных сообщений. Не включай `/spam_delete`, пока не проверишь правила с тестировщиком. Текст ссылок не отправляется на внешние антифишинговые сервисы. Защита от фишинга не гарантирована. Бот не банит пользователей.

Данные счётчиков используют уже существующую таблицу `processed`, дополнительных SQL-миграций не требуется. Записи продолжают накапливаться; для крупных групп потребуется фоновая очистка старых записей.

## v1.4 — удаление явного оффтопа и тест владельца
- Для явного нарушения правил ветки включено удаление сообщения + предупреждение, отдельное от антиспама. Кнопки /panel и команды `/topic_delete` / `/topic_warn`.

- Классификация только от ИИ **не удаляет** сообщения, даже при высокой уверенности: только предупреждение. Под явным оффтопом понимается только детерминированное `assess` из `src/rules.js`.
- Тест владельца: Telegram ID `5110155633` проходит модерацию как обычный участник, но сохраняет полномочия администратора в /panel. Включено по умолчанию, чтобы не нужен был второй аккаунт. После проверки **отключить `/selftest_off`** или через кнопку `🧪 Выкл`, иначе модерация будет затрагивать владельца.
- Для отладки: `/topics` в группе показывает привязки. Проверь в ветке «Баги» сообщение `Предлагаю добавить возможность менять цвет интерфейса QVK`, а в «Предложения» — `Приложение вылетает при открытии видео`.
- Пользователи-администраторы из `ADMIN_IDS` (кроме владельца в режиме самотеста) по-прежнему исключены из модерации.
- Дополнительная схема D1 не требуется. Боту необходимо право `can_delete_messages`.

## v1.5 — управление из личных сообщений
- В ЛС администратору из `ADMIN_IDS` доступна команда `/panel` или `/groups`.
- Бот показывает зарегистрированные группы, в которых он получил хотя бы одно сообщение после обновления. Выбери группу, затем «🗂 Ветки и назначение правил».
- Ветки запоминаются при входящих сообщениях и при событиях создания/изменения темы, если Telegram присылает эти события. Уже привязанные темы `topics` тоже показываются, даже если их название неизвестно.
- Нажми на тему и выбери «Баги», «Предложения», «Значки», «Общение», «Бета-релизы» или «Без тематических правил». Назначение сохраняется в существующую таблицу `topics`.
- Добавить не обнаруженную тему: «➕ Ветка по ID», затем ответить в ЛС, например `9 Баги`. Это добавляет тему в список без назначения: открой её и назначь правила.
- Можно изменить отображаемое название темы кнопкой «✏️ Изменить название». Команда `/cancel` отменяет ввод.
- Раздел «⚙️ Переключатели» управляет модерацией, ИИ, антиспамом, ссылками, очисткой вступлений и тестом владельца для выбранной группы.
- Полный список тем Telegram Bot API **не предоставляет**, поэтому необнаруженные темы необходимо активировать сообщением в них или добавить их ID вручную. Названия, созданные вручную, не меняют реальные названия веток Telegram.
- Не нужен новый SQL-файл: используется существующая `settings`, а уже созданные темы сохраняются в `topics`.
- После развёртывания напиши `/panel` в группе один раз, затем открой `/panel` в ЛС с ботом.
- Для регистрации событий `my_chat_member` можно расширить `allowed_updates` при установке webhook, но это не обязательно: группы обнаруживаются и из обычных сообщений.

## v1.6 — журнал, статистика и проверка прав
В личной панели `/panel` → группа добавлены разделы:
- **📊 Статистика:** суммарные предупреждения, действия за 24 часа, распределение событий по типам.
- **📜 Журнал:** последние 15 событий из D1 с временем UTC, веткой, Telegram ID пользователя и краткой причиной. Просмотр доступен только пользователям из `ADMIN_IDS`.
- **🩺 Права бота:** проверка текущих прав через Telegram `getMe` и `getChatMember`: удаление сообщений, ограничения участников, управление темами.

Раздел журнала показывает только события, уже сохранённые приложением; удалённые сообщения восстановить через него нельзя. Токен бота остаётся секретом Worker. Новая схема D1 не требуется.

## v1.7 — бесшумная панель и ручные наказания
- Личная панель при нажатии inline-кнопок использует Telegram `editMessageText` и меняет содержимое **одного сообщения**. Новое сообщение отправляется, только если редактирование не удалось (или бот ожидает текстовый ввод).
- В ЛС: `/panel` → группа → «👤 Участники и наказания» — выбрать пользователя из последних предупреждённых или ввести его числовой Telegram ID.
- Действия: снять одно предупреждение; вручную ограничить отправку сообщений на 1 час или 24 часа; снять ограничение. Они сохраняются в журнале событий. **Автоматического мута/бана нет.**
- Для мута бот должен быть администратором с разрешением **Restrict members**. Telegram запрещает ограничивать других администраторов; бот проверяет статус участника перед применением.
- При снятии ограничения используется `restrictChatMember` с разрешениями отправки; это может не восстановить прежние индивидуальные ограничения пользователя, если такие были установлены отдельно.
- Счётчик предупреждений хранится в существующей таблице `warnings`, удаление одного предупреждения не стирает историю событий. Новых таблиц и миграций нет.

## v1.8 — удобное оформление личной панели
- Меню групп, веток и настроек теперь выводят читаемые названия без технических идентификаторов на главном экране.
- Бот сохраняет имя и username участников по входящим сообщениям в существующую таблицу `settings` и показывает их в списке предупреждений, личной карточке участника и журнале.
- Для ранее зарегистрированных пользователей бот пытается получить имя через Telegram `getChatMember`; если Telegram не возвращает данные, выводится нейтральное «Участник» вместо выдуманного ника. ID остаётся в карточке для точного поиска и ручных действий.
- В журнале используются понятные подписи действий и названия известных веток. Технические действия и настройки в UI переведены на русский.
- Переключение разделов по-прежнему редактирует одно сообщение; при назначении роли ветке больше нет лишнего сообщения-подтверждения.
- Существующие таблицы D1 сохраняются, миграции не нужны.


## v2.0 — умная модерация, пороги наказаний, антирейд, аналитика и Telegram Mini App

- **Контекстная ИИ-проверка:** неоднозначное сообщение передаётся Workers AI вместе с текстом сообщения, на которое оно отвечает, когда Telegram предоставляет цитируемый текст. Тексты соседних сообщений в этой версии не сохраняются. Срабатывания только ИИ не вызывают автоматического удаления.
- **Система наказаний:** существующие предупреждения и ручные муты сохраняются. Новая настройка `auto_punish` (по умолчанию **off**) включает только уведомление о достижении порога (по умолчанию 3 предупреждения). Это **не автоматический мут и не бан**. Порог 2–20 меняется в Mini App.
- **Антирейд:** `raid_watch=on` обнаруживает 8 и более новых участников за минуту (порог 3–100), записывает событие и сообщает в группе. Одно уведомление на пятиминутный интервал. **Никаких автоматических ограничений или массовой блокировки**.
- **Аналитика:** события по дням и типам за 7 суток, активность веток; новые события `message_seen` содержат только ID пользователя, ID ветки, тип ветки и время, без текста сообщений. Исторические данные до обновления ограничены уже сохранённым журналом.
- **Mini App:** доступна по `/app` на домене Worker и из личной панели через кнопку «📱 Открыть Mini App». Сервер проверяет Telegram `initData` по HMAC-SHA256, срок действия 1 час, а также пользователя по `ADMIN_IDS`. API группы, аналитики, переключателей и порогов находится в `POST /api/app` и недоступно без этой проверки. Внешние секреты в браузер не передаются.
- **Необязательная переменная** `MINI_APP_URL`: HTTPS адрес страницы приложения, например `https://<worker>.<subdomain>.workers.dev/app`, если фактический домен отличается от стандартного.
- **Бот должен быть администратором** группы; включённые webhook обновления должны включать `message` и `callback_query`. Вступления фиксируются по `new_chat_members`.
- **База D1 не требует миграции:** используются таблицы `settings`, `processed`, `events` и `warnings`.
- **Проверка:** `npm test`, `node --check src/index.js`, GitHub Actions. В панели проверь переключатели, Mini App и права бота. Не включай автоматические санкции без отдельного решения администратора.

## Безопасные правила модерации — снижение ложных срабатываний
- **Баги:** обсуждение неисправностей, вопросы и уточнения разрешены; версия, медиа и подробный шаблон желательны, но не обязательны.
- **Предложения:** можно обсуждать существующие баги в контексте улучшения; смешанные сообщения не удаляются автоматически.
- **Значки:** заявки, вопросы о статусе и условиях выдачи не классифицируются как тематические нарушения автоматически.
- **Общение / Бета-релизы:** обсуждения, благодарности и ответы допускаются без тематических наказаний; публикацию релизов лучше регулировать вручную.
- Короткие ответы, вопросы и сообщения в ответ на другие сообщения защищены от автоматических тематических санкций. Неоднозначные и смешанные сообщения пропускаются.
- **ИИ-оценка теперь только для журнала ручной проверки** — сама по себе не выдаёт предупреждение и не удаляет сообщение. Автоудаление возможно только при чётком детерминированном совпадении и соответствующей настройке; оно не идеально, поэтому администратор может выбрать `/topic_warn`.
